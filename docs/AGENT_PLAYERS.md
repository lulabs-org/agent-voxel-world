# 接入 AI 玩家

CLI 与服务端托管 Agent 共用 `@voxel/agent-runtime` 的 Pi 执行器。模型通过 `pi-ai` 的 OpenAI-compatible 流式工具接口接入；`pi-agent-core` 负责“推理 → 工具 → 结果 → 再推理”，项目负责权限、任务、调度和世界状态。

## 代码职责与依赖

- `apps/agent-cli`：CLI 与环境变量解析；`apps/server`：任务安排、存储、控制台路由、唤醒和取消。
- `packages/agent-runtime`：`Session` 世界连接、`actions` 动作执行与建造、`runtime` 中的 `AgentRunner`、预算、工具、上下文和任务规则；`planner/models` 只查询模型目录。
- 公共入口不读取 `.env`、Pi 全局凭据或开发机器登录状态，也不自动启动 Agent。

模型依赖固定为 `@earendil-works/pi-ai@1.3.0` 与 `@earendil-works/pi-agent-core@1.3.0`。生产代码不再使用旧 `ModelPlanner`、`PiPlanner` 或 `AGENT_ENGINE` 开关。测试中的决策夹具仅用于独立验证共享业务规则；Pi 专项与 Colyseus 集成测试直接运行实际 Pi 核心及 SSE 适配器。

## 大厅控制台（推荐）

### 多轮工具执行

一次唤醒可以包含任意多轮请求，直到任务完成、等待、需要输入、阻塞、暂停、取消或预算耗尽。没有“一次唤醒一次请求”或“三次请求”限制。同一 Agent 只运行一个循环；正在运行时不会被定时器重复启动。不同 Agent 可以并发。

工具包括 `observe`、`chat`、`move`、`edit`、`build`、`house`、`wait`、`update_task`。工具按顺序执行，每个工具都校验参数和权限；错误后停止同批剩余工具，不回滚已确认的修改。模型自由文本不发送聊天或 TTS。普通问候可直接调用 `chat` 完成一次回复；创建或修改任务先调用 `update_task`，通过归属校验后才能修改世界。

- 移动、编辑和建造后重新观察，后续工具使用最新位置和版本；移动不足 0.05 格算失败。确认结果不代表自动寻路或已经实现全部目标。
- 请求未确认时记录未知状态，建造保存已完成、剩余及不确定坐标。恢复先观察核对，聊天与移动不自动重放。
- 普通新消息在工具边界让出执行；暂停、取消直接中断请求与动作。移动的最终停止输入在取消后仍会发送。
- 每个实际模型请求分别计入调用、token 和执行时间预算，包括失败或取消请求；服务没有返回用量时标记估算。关闭 SDK 隐式重试。任务创建/修改不重置已消耗额度。
- 当前任务保存最近 8 个完整模型轮次及成组工具结果；更早进度由任务摘要、蓝图和未确认动作保存。不进行后台摘要推理，不增加跨任务记忆。
- 公开问题和不同玩家私聊使用隔离上下文。私聊任务上下文、恢复信息及工具结果不进入其他人的对话。
- 每个世界写操作前等待检查点持久化；保存失败会停止后续写入。模型截断输出的工具批次不执行。

首次加载既有 Agent 存档会创建 `.before-pi.bak` 备份。Agent ID、语音绑定、任务归属、额度和建造进度保留。重启后任务保持暂停；原私聊会话失效时需在控制台重新安排，避免将私有上下文交给新的会话。

### 连续建造

开启“允许放置 / 移除方块”后，所有服务商的 Agent 都支持一次推理规划多块建造：

- `house`：用最小角坐标、宽深高、材质和门方向描述一座基础房屋，本地生成地板、空心墙壁、两格高门洞和平顶。宽/深 3–7 格，总高度 4–6 格；单个蓝图最多 192 块。
- `build`：一次提交 1–64 个具体方块修改，适合自定义结构、修补和拆除。坐标不能重复。
- 批次内约每 125 毫秒执行一块（上限约 8 块/秒，实际还取决于服务器响应），无需逐块推理或等待轮询间隔。每块等待服务器确认，沿用版本号、6 格距离、支撑、玩家占位等校验。
- 已存在且材质相同的方块会跳过；不同材质不会自动覆盖。房屋内部/门洞发现已有方块时，先报告障碍，不自动清理地形。中途停止不会回滚已完成方块。
- 遇到超距或障碍，返回完成数量、剩余坐标与失败原因。未完成蓝图保留到后续回合；模型需要移动站位或调整蓝图后继续，施工器不自动寻路。房屋应放在已观察到的空地上。

可以设置目标：“在附近空地使用 house 蓝图建造一座 3×3 小木屋，留出门洞；遇到超距先移动，再继续未完成蓝图，完成后报告结果。”一座 3×3×4 小屋包含 32 块，能由一次模型规划驱动，而非每块调用一次模型。较复杂的大房屋可以分段建造。

控制台运行记录会显示建造开始、阶段进度和完成/未完成数量。修改后需重载 Agent 服务，再创建新的 Agent；运行中的旧进程不会热替换施工逻辑。

无需先进入游戏。点击大厅中央的 **创建 Agent 玩家**，或右上角 **控制台**。控制台统一提供 **Agent 玩家**、**模型服务**、**文本转语音（TTS）** 和 **语音识别（ASR）** 四个页面；语音配置保存后可供多个 Agent 复用，试听在关闭或切换页面时停止。

1. 在 **模型服务** 中配置 DeepSeek、本机 Ollama 或 OpenAI 兼容服务。密钥仅保存在服务器。
2. 打开 **Agent 玩家 → 创建 Agent**，填写自定义昵称和可选的 **角色设定**，选择已保存的模型服务。模型 ID 与连接检测统一在 **模型服务** 页面配置，Agent 直接使用该服务保存的模型。
3. 选择角色技能与动作权限：建筑规划、探索勘察、导览讲解可多选；移动与跳跃、发送聊天默认开启，放置方块、拆除方块默认关闭。技能不会自动授予权限或发起任务。语音默认仅文字，可选择已保存的 TTS 服务并试听。
4. 默认 **先在世界中待命**，不要求填写任务，也不主动调用模型；收到私聊或 @ 后会调用模型回复。选择 **立即执行任务** 时必须填写第一个任务。
5. 任务额度在 **任务** 页安排任务或追加额度时设置。**任务** 页的 **任务心跳** 将间隔方式与时间并排展示，以秒输入，服务端仍使用毫秒；选择随机间隔时直接显示最短和最长时间，窄屏自动换行。心跳可独立保存，不会重置进度或恢复任务；执行中需先暂停再调整，后续任务沿用保存的设置。角色设置不再提交心跳字段；创建时仅“立即执行任务”显示心跳配置。间隔用于等待状态的观察检查，收到消息可提前唤醒；运行中的 Pi 工具循环不在每次模型请求之间等待心跳；无任务或等待条件未变化时不调用模型，心跳不会自动恢复已暂停或额度用尽的任务。推理超时、输出长度、思考模式和推理强度统一在 **模型服务 → 推理设置** 保存，所有使用该服务的角色从下一次调用起使用新参数。旧服务没有推理配置时沿用角色已有参数，首次保存服务后统一使用服务参数。

角色列表支持全部、在线、待处理和离线筛选；角色较多时显示名称搜索。选中角色后，右侧工作区分为 **任务**、**角色设置**、**运行记录**。在线状态与任务状态分别显示，已完成任务不会被误当成离线角色。运行记录展示累计用量、最近回复与最近 40 条记录，最新记录在上。

### 聊天与任务

- 普通私聊、群聊 @、可听范围内真人语音转写：处理当前消息一次。问候、询问进度不会重新启动旧任务。
- 行动指令执行后会私密回执给发送者；格式错误、预算不足也会提示，避免静默丢弃消息。移动后会继续观察自身位置，不以方块变化作为确认移动结果的条件。
- 明确的任务指令：模型返回 `task` 决策，创建任务；补充要求用 `update`，保留原任务上下文和未完成蓝图。
- 每步根据观察和动作结果决定继续、完成、等待环境变化、请求用户输入或报告阻塞。实际编辑/移动后至少再观察一次才能标记完成，未完成蓝图不能直接宣称成功。
- 等待时只在本地比较附近方块或玩家位置；条件未变不调用模型。已完成、暂停、取消、阻塞或预算耗尽均不自动推理。
- 连续三次动作失败或没有实际进展会停止自动尝试。语音/文本回复不会成为另一个 Agent 的自动唤醒源。
- 正在执行时收到消息会排队，最多 8 条并去重。同一角色一次只运行一个 Pi 循环；明确的“暂停”“暂停任务”“停止”“别建了”“取消任务”可直接中断推理/施工，不需要模型判别。其他表达由下一次模型决策判断。

**发送范围不决定执行次数**。私聊可以布置任务，群聊 @ 也可以只是问候。私聊任务保留原接收范围，后续任务汇报也只发送给发起者；公共问题不会收到私聊任务的上下文。任务由玩家发起时，只允许该会话修改当前任务；控制台可覆盖安排。普通群聊、历史消息和 Agent 消息不唤醒。

### 任务安排与独立执行

任务页默认显示任务列表。每个角色可以保存多个安排：立即执行一次、指定日期时间执行一次，或按固定间隔、每天、每周重复。每次执行包含多轮规划和动作；长期建造目标使用一次性任务，暂停后继续同一条执行记录。

新建时填写名称、目标与完成条件、执行方式。时间字段按执行方式出现；时区使用创建时浏览器的 IANA 时区并保存。执行限制使用复选框，默认开启；勾选后显示额度设置，取消后不限制调用次数、tokens、有效执行时间及重复计划累计 tokens，实际用量仍持续记录。旧存档未包含开关时保持原有限制。点击任务查看安排、未结束执行和分页历史；Agent 汇报、实际动作结果、异常原因和用量分别展示。

**计划操作**包括立即执行、暂停/恢复计划、编辑和归档。暂停计划只停止后续触发，不暂停当前执行；编辑只改变未来执行，旧记录保留原目标和额度快照。归档要求所有执行已结束，历史不会删除。

**执行操作**包括暂停、继续和结束本次执行。暂停保留目标、进度、用量与建造检查点；继续前角色必须在线且空闲。重新执行新增记录，不覆盖历史。每个角色同时最多执行一条任务，暂停或异常记录不占执行名额。

固定间隔以创建时间为锚点，首次在一个间隔后触发；手动执行不移动下次时间。日历规则按保存的时区计算，UTC 时间戳落盘。夏令时不存在的时间跳过，重复时间仅执行第一次。恢复计划只计算未来时间，不补跑。多个计划同时到期时按触发时间、创建顺序选择；其他记录忙碌跳过。离线时不会自动上线，重复安排跳过、一次性定时安排标记已错过。

执行异常、受阻、需要补充信息或额度用尽时暂停对应计划。处理后须显式恢复计划；继续本次执行不等于恢复计划。服务端负责调度，关闭浏览器不影响任务；世界服务停止期间错过的触发不补跑。心跳为执行器内部节奏，旧固定/随机配置保留，新角色默认 3 秒，角色设置不再展示调度或任务额度。

最多同时在线 4 个托管 Agent（含待命）。离开世界暂停正在执行的任务；加入世界待命只上线，不重跑旧记录。聊天产生的新任务登记为立即执行的一次性安排，不能隐式替换正在执行的任务。普通回复保持原有消息唤醒和私聊隔离。

**角色设置** 可修改昵称、角色设定、模型服务、权限与语音服务。任务目标只在“任务”页修改，保存角色设置不会把旧表单中的目标覆盖到新任务。执行中显示暂停入口，暂停后才能保存；语音回复开关仍可在运行期间切换。更换模型会重置任务进度。单独修改技能或动作权限会暂停未结束任务，保留目标、用量、动作记录和建造检查点；确认继续后按新能力重新规划，不重放旧动作。已完成、已取消任务保持原状态。

**能力规则**：内置技能提供专业规划指导，基于现有世界动作执行，不代表新增自动寻路或完整地图。技能所需权限未开启时可以保存，但界面会提示执行限制。动作解析和执行边界均校验权限，批量操作在执行前检查所有步骤；`house` 需要放置权限，`build` 的每一项按放置或拆除分别校验。关闭发送聊天权限后，文字、自动回执和语音回复均停止，控制台仍显示任务进展；已选音色与语音偏好保留，重新开启聊天后生效。观察与等待始终可用。

**兼容旧配置**：`permissions` 是新权限依据，`skills` 保存固定技能标识。没有 `permissions` 的旧配置默认允许移动和聊天，`allowEdits` 同时映射为放置与拆除；旧角色的技能列表为空。CLI 的 `AGENT_ALLOW_EDITS` 继续兼容，Web 与 CLI 使用同一个共享执行器。无需手动迁移数据。

**角色设定** 是长期的身份、职责与交流方式，最多 2000 字，可留空。例如：“你是一名建筑师，负责规划和建造房屋。施工前先确认位置、尺寸和风格，遇到障碍先说明情况，用简洁的中文汇报进度。”它随角色保存，重启后保留，在后续对话和任务规划时提供给模型。单独修改设定不清空任务进度、不启动推理，也不授予建造权限；实际施工仍需开启 **放置方块**（需要拆除时还需 **拆除方块**）并安排具体任务。旧角色没有设定时保持原有行为。

启用执行限制时，“任务额度”中的 `maxTurns` 是任务调用保护上限（默认 100，范围 1–200），不是执行轮数。另有任务 token 预算（默认 50,000）和有效执行时间上限（默认 15 分钟，累计模型与动作耗时，不计等待）。达到上限后停止，控制台提高本次执行的总上限并确认继续，已有调用、tokens 和有效执行时间不清零。重复计划另有默认 500,000 tokens 的累计额度，所有来源的执行均计入，人工追加后保留历史累计用量。旧 `continuous` 只保留读取兼容，不再绕过限制。

模型返回 usage 时记录真实 token 数；缺少 usage 时用输入字符与最大输出长度估算并标记“约”。预算在每次调用前和结束后检查，最后一个请求可能超过剩余 token 额度，不能当作供应商账单的硬限额。问候等独立消息计入累计用量，不重新申请任务额度。

### 保存与恢复

配置、任务摘要、逐动作批次结果、未完成蓝图和用量保存在 `.data/agent-providers.json.agents.json`（`0600`，不含 API Key）。服务重启后恢复原在线角色为待命，未完成任务暂停，不自动调用模型。仅恢复批次格式的执行历史，不再转换旧单动作结果；重启时尚在执行的步骤标为结果未知，剩余动作不自动重放。迁移前创建 `.before-task-plans.bak` 备份；任务数据写入版本为 1 的 `taskBook`。每个旧任务迁移为一次性安排和一条执行记录，未结束任务暂停，已完成/取消状态保留。中断的执行保留检查点且对应计划暂停；显式关闭的角色保持关闭。游戏会话和位置仍由世界服务管理；方块持久化取决于世界存储设置。

私聊接收者是游戏会话 ID，不是账户身份。服务重启后原私聊会话失效，私聊任务保持待确认，需在控制台重新布置，不能按同名玩家自动转交。最多保存 50 条 Agent 记录。

服务商保存在本机 `.data/agent-providers.json`（文件权限 `0600`，未加密，请勿分享或提交）。首次启动自动导入 `DEEPSEEK_API_KEY` / `DEEPSEEK_MODEL` / `OLLAMA_MODEL`；已有配置文件后以控制台保存值为准，修改 `.env` 不会覆盖它。页面仅收到 `hasApiKey` 状态；编辑时留空保留密钥。更换地址域名或服务类型必须重新填写密钥。删除服务商不会删除世界方块。

通用服务必须兼容 OpenAI **Chat Completions** 的 SSE 流式响应、工具调用及 `tool_choice=required`；不支持时明确报错，不降级到 JSON 文本解析。原生 Anthropic/Responses 等接口本期未接入。可在兼容设置中选择 `max_tokens` 或 `max_completion_tokens`。旧 `jsonMode` 字段可读取但不再生效，控制台已移除该选项。DeepSeek 专用思考字段不会发给其他服务商。本机 Ollama 使用 `http://127.0.0.1:11434/v1`，先在 Ollama 下载模型，再获取列表；配置 Ollama 失败不影响使用 DeepSeek。[Ollama 官方兼容接口说明](https://docs.ollama.com/api/openai-compatibility)。

管理 API 仅接受 `WEB_ORIGIN` 指定页面的 Origin，世界服务仍只绑定本机。`GET /agents/providers` 返回脱敏配置，`POST/PUT/DELETE /agents/providers[/id]` 管理服务商，已有可复用 Agent 关联的服务商不能删除。`GET /agents/providers/:id/models` 查询模型，`GET/POST /agents` 查看/创建玩家（新建传 `startTask: false` 表示只加入待命，可省略 `goal`；省略此开关保持原有创建并执行语义），`PUT /agents/:id` 保存已有 Agent 参数（不启动），`POST /agents/:id/task` 布置任务（传 `goal`），`POST /agents/:id/pause` 暂停，`POST /agents/:id/cancel` 取消，`POST /agents/:id/resume` 手动继续（可传 `goal` 新建），`POST /agents/:id/join` 仅加入世界待命，`POST /agents/:id/stop` 离开世界并暂停执行中的任务。写请求使用 JSON。它是本机原型的管理接口，不应直接暴露到公网。

### 任务管理 API

以下接口沿用 `/agents` 的 Origin 与 JSON 校验。Web 访问集中在 `features/console/api.ts`。

| 接口                                                          | 用途                                |
| ------------------------------------------------------------- | ----------------------------------- |
| `GET/POST /agents/:id/tasks`                                  | 安排摘要列表 / 创建                 |
| `PUT /agents/:id/tasks/:planId`                               | 修改未来安排                        |
| `POST /agents/:id/tasks/:planId/run`                          | 手动新增执行，必须提供 `requestId`  |
| `POST /agents/:id/tasks/:planId/pause`、`resume`、`archive`   | 计划控制                            |
| `POST /agents/:id/tasks/:planId/extend`                       | 追加累计额度，JSON `{tokens: 数量}` |
| `GET /agents/:id/tasks/:planId/runs?offset=0`                 | 每页 20 条记录及所有未结束执行      |
| `POST /agents/:id/task-runs/:runId/pause`、`resume`、`cancel` | 本次执行控制；继续可传更高的总额度  |

创建支持 `requestId`，相同标识重试返回原安排。手动执行按请求标识去重，自动触发按计划 ID 和计划时间去重。执行记录和占用先成功保存，再开始模型调用；保存失败不启动执行。所有存储沿用本机原子文件替换，无新增数据库依赖，仅支持单服务实例。

旧 `/task`、`pause`、`resume`、`cancel` 接口保留兼容并使用同一份执行记录。旧 `/task` 仍显式暂停当前执行后创建新任务；新的任务 API 不隐式替换。模型不能创建定时规则、恢复计划或扩大额度。CLI 仍是单任务运行，不启动调度服务。

## DeepSeek 命令行（仍可使用）

### 配置与启动

在项目根目录现有 `.env` 中追加以下配置，保留已有数据库等设置。也可以通过环境变量传入；环境变量优先。不要提交 API Key，不要使用 `VITE_*`。

```dotenv
DEEPSEEK_API_KEY=你的DeepSeek_API_Key
DEEPSEEK_MODEL=deepseek-flash
AGENT_NAME=DeepSeek
AGENT_GOAL=探索附近环境，用中文简短介绍你的观察，友好回应玩家。
AGENT_MAX_TURNS=100
AGENT_TOKEN_BUDGET=50000
AGENT_TASK_TIMEOUT_MS=900000
AGENT_ALLOW_EDITS=false
```

启动最新代码的世界服务，再运行独立 Agent 进程。默认世界端口为 2567；当前浏览器 5187 对应的开发世界使用 2577：

当前 memory 模式在普通重启时会丢失方块编辑；更新运行中的世界前须先备份/恢复，或使用数据库持久化配置。

```sh
SERVER_URL=ws://127.0.0.1:2577 pnpm agent:ai
```

顶部“玩家”面板将显示 AI 代理身份，模型每轮可以选择移动、聊天或等待。`Ctrl+C` 取消模型请求、停止移动并退出世界；任务完成、等待条件、需要输入或达到保护上限时结束本次 CLI 执行并退出；需要在线待命和事件唤醒请使用控制台托管 Agent。模型配置/认证/余额错误直接结束，其他连续三次失败也停止，不会无限重试。脚本测试机器人可运行 `pnpm agent:mock`。

DeepSeek API 需要有效 API Key 和账户可用额度。运行时会把 Agent 目标、附近方块、玩家昵称和近期公共聊天事件发送给 DeepSeek；没有浏览器音频、文件或环境变量读取工具。

## 思考模式

默认 `thinking: {type: "disabled"}`、每轮最多 512 输出 token，减少交互等待。与官方 SDK 示例相同的思考模式：

```dotenv
DEEPSEEK_THINKING=enabled
DEEPSEEK_REASONING_EFFORT=high
DEEPSEEK_MAX_TOKENS=4096
DEEPSEEK_TIMEOUT_MS=60000
```

未设置 `DEEPSEEK_MAX_TOKENS` 时，开启思考默认 4096，关闭默认 512。工具调用输出被截断时整批不执行；可适当提高输出上限或关闭思考。SDK 自动重试已关闭，一次唤醒可执行多轮，所有请求都受任务预算控制。

## 可执行动作和边界

- 每批 `actions` 包含 1–8 个以下动作，共享一个 `task` 决策。
- `wait`：结束当前序列，等待下一次观察；只允许位于末尾。
- `chat`：1–240 字公共消息。
- `move`：世界坐标方向 x/z 在 -1..1，跳跃布尔值，持续 100–1500ms；本地以 10Hz 发送输入，取消或结束后发送停止输入。
- `build` / `house`：连续编辑或房屋蓝图，每批最多一个，限制见上文。
- `edit`：需显式设置 `AGENT_ALLOW_EDITS=true` 才允许放置/移除方块。使用观察时的世界版本，服务端继续检查距离、碰撞、基岩、边界和版本冲突。被拒绝的编辑不会自动重放。

`AGENT_MAX_TURNS` 范围 1–200，现在只作为单任务调用上限。旧 `AGENT_CONTINUOUS=true` 不再绕过预算。间隔 `AGENT_INTERVAL_MS` 默认 3000，范围 1000–60000。随机间隔示例：

```dotenv
AGENT_INTERVAL_MODE=random
AGENT_INTERVAL_MIN_MS=4000
AGENT_INTERVAL_MAX_MS=8000
```

上下限均为 1000–60000 的整数，下限不得大于上限，相等时为固定间隔。省略模式时使用 `fixed`。间隔只控制等待观察和事件唤醒；一次唤醒中的 Pi 请求不受此间隔限制。

每次输入最多 500 个附近方块、16 个玩家、当前明确发来的事件、任务摘要和上轮动作结果。没有任意 shell、文件系统或网络工具。AI 身份与脚本身份一样只是显示标签，不授予额外权限；本机原型仍没有账户认证。

模型自主表现需用真实 Key 实测。Pi 专项使用 SSE 工具调用响应验证真实适配器，并在独立 Colyseus 世界验证移动、聊天、编辑与建造；确定性集成测试不调用付费模型。真实模型对比单独报告，不将固定响应作为模型效果证据。

```sh
pnpm check
pnpm test:agent:tasks    # 任务与单次唤醒、暂停、预算、私聊隔离
pnpm test:agent:deepseek  # 自动启动独立临时世界，不触碰正在玩的世界
pnpm test:agents          # 多服务商管理、Origin 校验、密钥脱敏、并发/停止/清理
```

接口依据：[DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion)、[Pi Agent Core](https://github.com/earendil-works/pi/tree/main/packages/agent)。

### Agent 工作区隔离验收

以下预览只使用临时文件、内存世界和固定模型响应，不加载 `.env`、现有 Agent 或真实密钥：

```sh
pnpm --filter @voxel/server exec tsx test/sandbox/agent-console-sandbox.ts
VITE_SERVER_URL=ws://127.0.0.1:2589 pnpm --filter @voxel/web exec vite --host 127.0.0.1 --port 5189
```

打开 `http://127.0.0.1:5189/`。可验证创建待命、任务提交、暂停后编辑、继续、离开与再次加入；目标包含“等待”时固定返回等待状态，包含“循环”时持续推进至预算保护。`http://127.0.0.1:2589/fixture-status` 可查看模拟调用计数。使用 Ctrl+C 结束这两个测试进程，后端会清理临时数据。日常开发服务不受影响。

任务管理按目标、当前状态与原因、执行结果和资源用量分别展示。执行结果中的最近汇报来自 Agent，可能包含计划，不视为已验证的动作成果；实际执行情况在运行记录中查看。调用次数、token 和有效执行时间独立显示用量与上限，达到上限的项目单独提示，不将资源消耗展示为任务完成进度。新建/修改任务时应说明范围、预期结果和完成条件；聊天中的任务修改保留当前任务历史和累计额度；控制台明确安排新的执行时才建立新的任务额度，已有世界改动保留。结束任务仍使用取消语义，不会标记为成功完成。

## Pi 迁移、验收与回退

真实模型比较使用固定的内存世界，六类场景各 5 次：聊天、移动、建造、纠错、等待、中途修改。它衡量模型决策和运行器，不替代 Colyseus 物理、权限、浏览器和语音集成测试。命令会消耗所选服务的实际模型额度：

```sh
pnpm exec tsx tests/benchmarks/pi-agent.ts
# 可选：PI_BENCHMARK_PROVIDERS 指向配置文件，PI_BENCHMARK_PROVIDER 选择服务 ID。
# 结果默认写入 artifacts/pi-migration/pi-benchmark.json；可用 PI_BENCHMARK_OUTPUT 修改。
```

旧版比较从被比较提交导出 `packages/agent-runtime` 到独立目录（不修改工作区），为该目录提供相同依赖；设置 `PI_BENCHMARK_BASELINE_ROOT` 指向导出的包根目录即可。生产包没有旧后端或运行时切换开关。比较每类成功数、请求数、token 与端到端延迟的中位数；成功数不得低于旧版，token 或延迟增加超过 20% 时先分析优化。

切换前停止所有 Agent，等待检查点落盘，备份 `voxel_server_data` 中的配置、任务存档与既有世界数据，保存旧 server/web 镜像标签。只替换 server/web，不删除 PostgreSQL 或语音模型卷。新版本启动会保留旧任务进度，暂停运行中的任务，不重放未知动作。

回退时先停止新版本 Agent 和 server，保留新的数据副本；使用上一版 server/web 镜像及其对应的配置/任务备份。先核对实际世界中的建造和移动结果，再决定任务如何继续；不要直接重放备份中的未知动作，也不要把旧任务备份当作世界状态。具体本机验证记录见 [VALIDATION.md](./VALIDATION.md)。
